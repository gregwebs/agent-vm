# Files the host Python guard (no-host-python.sh) accepts. ADR-0072 requires
# that building and testing the repository needs no `python3` on the host.
#
# Format: a `*.py` file is a bare path; a `*.sh` or `*.rs` file carries the number
# of Python occurrences it excuses. A count that is too low means a new call got
# in, and one that is too high means a port left it behind. Both fail, so this is
# a ledger of debt with a running total, not a per-file veto.
#
# The closing ledger (#701) has five rows, none a `.py` file, and 20 excused
# occurrences.
#
# Three kinds of entry:
#
#   Guest exceptions - Python that runs inside the guest, not on the host.
#   Permanent, unless the guest image drops Python.
#
#   Vendor tooling - upstream's own Python, which this repository does not own.
#   Out of scope, like the libkrunfw build's pyelftools.
#
#   Fixture stub names - a `python3` a harness check writes as a file, never
#   runs. Its count is what keeps a real call from hiding among the names.

# --- Guest exceptions -------------------------------------------------------
# The CPU evidence workload: three guest command strings plus the name of the
# workload file the driver writes into the guest.
crates/agent-vm/src/cpu_evidence/native.rs 4
# The guest half of the egress probe: TLS and socket probes, with a node
# fallback. #693 ported its host-side callers — the wire and dispatcher controls
# run `harness egress-probe` and drive the pure-bash primitives through bash — so
# what is left is the guest's, and the count stays.
script/test/fixtures/egress-probe.sh 10

# --- Vendor tooling (libkrunfw bin2cbundle.py), out of scope per #682 -------

# --- Fixture stub names, not invocations -----------------------------------
# This harness check writes a deliberately broken `python3` onto a scratch PATH
