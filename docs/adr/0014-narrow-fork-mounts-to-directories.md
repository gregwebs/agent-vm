# ADR-0014: Narrow fork mounts to directories; files are read-only

## Status

Accepted. Implementation decision for [agent-vm #113](https://github.com/gregwebs/agent-vm/issues/113). Narrows [ADR-0013](0013-add-forked-mounts.md): the identity, store, locking, publication, and fail-closed recovery decisions there remain applicable; only its file-root fork and live-exclusion masks are superseded. The descriptor-pinned symlink/ACL hardening is deferred to [agent-vm #114](https://github.com/gregwebs/agent-vm/issues/114).

## Context

ADR-0013 let `:fork` copy either a file or a directory and let `:exclude=REL` on a live bind create an opaque mask to hide nested paths. Both turned out to carry more surface than they were worth:

- A file-root fork duplicated the runtime's writable-file staging path with its own cross-device and lifetime hazards, while a single file is rarely the natural unit to copy.
- Live exclusions required materializing opaque masks (a shared readonly file plus readonly tmpfs directories) and then proving that no nested or symlink-alias mount could pierce them. That alias-piercing analysis was the largest and most fragile part of `mount.rs`.

Meanwhile the fork lifecycle that users actually relied on — seed once, reuse independently, reset by removing the printed directory — is a property of copying a **directory**, and the runtime's per-bind root-follow opt-in (`follow_root_symlinks`) already gives the launch layer what it needs without new runtime behavior.

## Decision

- **`:fork` is directory-only.** A file (or symlink-to-file) fork root is rejected with `--mount <src>: a :fork source must be a directory. Fork the containing directory, or bind the file read-only with :ro.` The copy engine still copies every nested regular file and, under `:fork:follow-links`, materializes followed file targets — only the root is constrained. The root is enforced on the descriptor actually opened for copying (`O_DIRECTORY`), not only at policy time, so a root swapped after classification fails closed.
- **A regular file is mounted read-only.** A bare or `:rw` file mount is rejected with a message naming the source and the `:ro` / containing-directory alternatives. `:ro` files remain ordinary read-only binds; no writable single-file mount exists.
- **`:exclude=REL` is fork-only.** It omits entries during seeding (normalized, repeatable, ancestor-collapsed) and is a parse error on any live bind. Omissions are seed-only physical content removal, not a persistent guest access restriction: the guest, or an explicit later child mount, can populate an omitted path.
- **Opaque masks and their alias validation are removed.** `PreparedVolumeSource` is exactly `WritableBind`/`ReadOnlyBind`; `VolumeRole::Mask`, the mask file, tmpfs masks, and the physical/composed alias checks are deleted. This intentionally removes the alias-piercing restrictions ADR-0013 added; ordinary mounts cannot "pierce" anything that no longer exists.
- **Repo scanning reads physical committed content.** A prepared fork contributes its committed `data`; an excluded `.git`/`.gitmodules` is simply absent from the copy, so the scanner needs no logical exclusion filter.
- **The runtime interface is ordinary binds.** `run::launch` binds each prepared source as a plain writable directory bind or read-only directory/file bind, opting into per-bind root follow (`follow_root_symlinks(true)`) so a user's symlinked source spelling resolves once. Core volumes (HOME, project, state) deliberately keep root follow at the default `false`; their sources are canonicalized only after provisioning creates them, and a fresh state root stays valid.
- **Identity and manifest versions are unchanged.** `MANIFEST_VERSION = 2` and `IDENTITY_VERSION = agent-vm-fork-identity-v2` are retained so valid directory forks keep their identity and unsupported entries are found rather than orphaned. The serialized manifest field stays `kind`. A READY entry whose manifest `kind` is `file` fails closed with an actionable error naming the exact directory to remove; nothing is reseeded, migrated, truncated, renamed, or deleted automatically.
- **Transaction guarantees are unchanged and bounded.** `prepare` validates all declarations, fork READY state, topology, and core collisions before the first state mutation. `prepare_forks` then locks per identity, rechecks READY, seeds into staging, and atomically renames to `READY`. Deterministic policy/topology rejections are side-effect free; copy I/O errors, a concurrently mutating source, or a killed initializer may leave retryable locks/staging, and there is no cross-fork rollback or power-loss durability promise.
- **Dependency pin.** The launch layer relies on the microsandbox `main` baseline at `f948475c6cc8bc28b4decb96d8b40442f5635293`: its per-bind `follow_root_symlinks` builder method (default `false`) and its existing no-follow-root-resolution default. Descriptor-pinned symlink/ACL hardening — the `crates/filesystem/lib/nofollow.rs` resolver, the Darwin ACL cleanup-swap guard, and the file-bind classifier/staging routing — is **deferred** to [gregwebs/agent-vm#114](https://github.com/gregwebs/agent-vm/issues/114), because the only branch carrying it entangles it with the fork-era writable cross-device staging.

## Consequences

- Removing the masks is not a re-opened hole for *files the host must keep out of the guest*: [ADR-0020](0020-protect-host-pi-credential-files.md) refuses a live bind that would expose a host Pi credential file rather than masking it, and has forks omit it. Nothing removed here is re-added.
- The CLI is **breaking**: file forks and live exclusions now fail. Migration is explicit — a file fork becomes a `:ro` file bind or a fork of its containing directory; a live exclusion becomes a fork with `:exclude`. Live `:follow-links` remains read-only directory discovery, not a way to hide paths. There is no automatic diff/apply or migration mechanism.
- Fork seeds pay full eager copy disk cost and are not a point-in-time snapshot of a concurrently changing source.
- Runtime hardening is **deferred** to [gregwebs/agent-vm#114](https://github.com/gregwebs/agent-vm/issues/114): the pinned dependency does not include the descriptor-pinned `nofollow` resolver, the Darwin ACL cleanup guard, or the file-bind classifier/staging routing. The pinned runtime stages file binds in a temporary directory and falls back to a copy across filesystems; it does not carry the donor branch's writable source-parent staging. Agent-vm rejects writable file declarations before reaching the runtime. Upstreaming this narrowing and runtime-owned source-parent sweeping remain out of scope. The pin also lacks the donor's no-follow guest file-target preparation; this decision makes no descriptor-pinned host resolution, ACL cleanup, or guest mount-race safety claim.
